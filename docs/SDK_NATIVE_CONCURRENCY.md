# SDK 0.1.25 原生并发规则

Web → Go Server → Go Agent → Node Scanner 的输入、HTTP 控制接口、共享产物与 JSONL 事件传输保持不变。SDK 仍锁定 `@openai/codex-security@0.1.25`。本次只放宽数量参数和任务调度，不启动真实模型或认证。

## 已移除的平台上限

| 入口 | 原平台规则 | 当前规则与 SDK 映射 |
| --- | --- | --- |
| Deep Worker | 1–64 | 正安全整数；原值传给 `CodexSecurity.run().workers`，留空省略 |
| 每个 Worker 的子代理 | 0–64 | 非负安全整数；原值传给 `subagents`，显式 0 保留，留空省略 |
| 组件并发 | 1–8 | 正安全整数；原值传给 `runComponentScans().workers`。Web 初始值与 SDK 默认值一致为 4；原生调度器自然按 `min(workers, 本轮组件数)` 执行 |
| Deep 发现次数／连续无新增次数 | 1–1000 | 正安全整数；原值传给 `maxDiscoveryRuns` / `stopAfterNoNew`。网页提交处理器不再重复限制 1000 |
| 旧节点槽位上报 | 最多 64 | 允许安全整数诊断值；当前 Agent 仍使用显式 `unbounded + slots: 0`，该值不参与任务数准入 |
| 同一 SDK 身份的父任务 | 整轮串行 | 配套新节点允许并行，任务使用独立 SDK 状态；ChatGPT 凭据从执行私有快照读取，只在复制与写回时短暂互斥 |

安全整数上限是 JavaScript `Number.MAX_SAFE_INTEGER`（9007199254740991），来自 SDK 的 `Number.isSafeInteger` 校验，不是新的资源配额。负数、小数、非有限数及超过安全整数的值在 Web、HTTP 和 Go/TS 合同边界拒绝。新建请求显式填写发现次数 0 会被拒绝；历史存储的 0 继续表示未配置，不改写历史快照。

## 凭据并行与正确性

API Key 使用既有按 Agent / 身份 / generation 隔离的凭据。ChatGPT 每次执行先通过 SDK 的公开 `importAmbientAuth()` 复制不透明的 `auth.json`，将私有副本作为该执行的凭据来源。凭据不进入任务产物、Server 数据库或 Web 响应。

扫描正常关闭后，Scanner 只在共享凭据仍与启动时快照一致时原子替换 `auth.json`；已被其他执行刷新时保留新版本，不用较早快照覆盖。不会解析 token 字段，也不会替换或复制工作台、源码。身份 generation 发生变化时拒绝写回。复制和写回的短临界区使用 SDK 身份私有目录中的 SQLite OS 锁，进程崩溃后自动释放；该文件不保存凭据，不新增 Agent 数据库依赖，也不改变 Server 业务数据库边界。

登录、账户查询和撤销仍与使用该身份的活动执行互斥；撤销会请求停止全部绑定执行，确认执行结束后再清理凭据。执行租约、费用未知阻断、源码身份、路径边界及存储可用性检查继续生效。这些是状态一致性检查，不添加 Worker 或父任务数量配额。

## 合同、版本与数据库

- `sdk-concurrency-compatibility.json` 记录原生整数域及旧节点兼容阈值，由同一生成流程校验 Go/TS Schema。阈值只用于识别旧读取器的能力，不用于截断输入。
- Scanner Description v12 显式声明 `sdkConcurrencyVersion: 1`，并确认 SDK 0.1.25；控制 API 4 协商同名能力。
- 超过旧数值域的任务要求节点声明该能力，并有最近 30 秒内有效的 v12 运行上报。旧、缺失、未知或过期能力都不能领取；Web 提示同步更新 Agent 与 Scanner，不自动降低数值。Agent 还会核对已领取任务。
- 原有字段、Job/Assignment 版本、SDK 参数侧带和历史读取器保留；现有数量字段只放宽数值域。旧任务、报告及结果无需重写。旧节点仍可领取其已支持范围内的历史任务；同身份并行仅对已确认新能力的节点开放。
- 迁移 `024_sdk_native_concurrency.sql` 将数量列扩为 `BIGINT` 并放宽 CHECK，保留行、关系、attempt 和历史证据。生产 PostgreSQL 升级仍先发布 Server，再配套更新 Agent / Scanner 和 Web。历史迁移文件不修改。

## 保留的主动配置与数据容量

Web 主动配置的单次预算、累计预算、超时、源码／Git／组件范围及停止条件继续冻结和执行，不会因为放开并发而删除或扩大。SDK 的原生 96 小时边界不改变；当前 Web 已有的时间配置保持原有语义。原生匹配费用仍可能未知，不伪装为 0。

计划条目数、进度快照数量、事件／报告文档字节和数据库连接池属于数据或连接容量，不作为扫描并发配额；本次不把它们改成虚假的“无限容量”。例如组件实际并发仍受该冻结计划本轮所选组件数约束，进度快照截断仍有显式标记，完整事件按原机制归档。

## 验收

验收使用一次性 PostgreSQL 与标记明确的 Fixtures / Mock。覆盖 Go/TS 双向编码、安全整数边界、历史读取／迁移、旧节点和过期能力拒领、Web 提交 129 个 Deep Worker／65 个子代理／1001 次发现及 9 个组件并发的 SDK 入口、原生调度器 9 组件同时执行、凭据并发写回 CAS 和崩溃锁释放，以及预算／时限／范围保留。浏览器检查桌面和窄屏、非法值、保存失败保留输入、兼容提示与历史报告。

这些测试证明参数和状态链路，不证明真实模型吞吐、上游账户额度或真实登录刷新兼容性。没有执行真实规划、审计、SDK 登录或外部发布。
