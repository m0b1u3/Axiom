# 账户、会话与权限基线

2026-10-14，步骤 7。保留 Go Server + Go Agent + Node Scanner / SDK，以及现有 HTTP、共享目录和 JSONL。账户与扫描操作都通过 Web 完成。本轮验收不调用真实模型。

## 密码与旧账户

新建账户和 Web 改密使用 Argon2id：19 MiB、2 次迭代、并行度 1、随机 16 字节 salt、32 字节派生值，保存为 PHC 字符串。参数采用 [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) 的最低基线，实现使用 [Go x/crypto/argon2](https://pkg.go.dev/golang.org/x/crypto/argon2)。新密码至少 12 个 Unicode 字符、最多 1024 字节；登录仍接受原有短密码，使旧账户能够迁移。

旧 HMAC 密码仅用于验证历史账户。成功登录后，以事务和旧散列 CAS 升级为 Argon2id，保留用户 ID、用户名和密码；启动配置不重置已存在账户的密码。新散列与签名密钥独立。

首次升级保留原 `AXIOM_JWT_SECRET`，旧 Web 令牌需要重新登录。若在仍有 HMAC 账户时轮换签名密钥，设置 `AXIOM_LEGACY_PASSWORD_SECRET` 为旧签名密钥，保留到旧账户全部成功登录迁移。Argon2id 账户不依赖该旧密钥。此可选配置已接入正式 Compose，备份仍需私密保管配置和 master key。

默认开发账户仍为 admin/admin，仅适合本地开发。正式启动强制检查密码及独立密钥。登录 KDF 并发最多 4 个，导入散列的参数有上限，防止损坏记录触发无限计算或内存分配。

## 持久化会话

访问令牌包含格式版本 2、用户 ID、随机 32 字节会话 ID、账户版本和到期时间；数据库只存令牌 SHA-256，不存原始令牌。每次请求都验证签名、会话归属、散列、到期时间、账户版本及启用状态。旧无会话令牌不被接受。

会话有效期 24 小时，每个账户最多 10 个有效会话；退出和 Web 撤销会话在数据库中生效。改密、角色或账户启用状态变更以同一事务提升账户版本并撤销全部会话。签名密钥变更也使旧令牌失效。Server 重启或替换保留有效会话；备份恢复到新环境会提升账户版本并撤销恢复的旧会话，需重新登录。

Web 在网络或数据库故障时显示重试提示，退出未被确认时保留当前令牌；401 才跳回登录，403 保留登录。旧请求迟到的 401 不会清除后来建立的新会话。数据库故障返回 503，不能伪装成密码错误或会话过期。后台扫描生命周期独立于浏览器会话。

## 权限范围

这是一个共享工作空间的角色权限基线。所有启用账户共享项目、源码、漏洞与历史报告读取权限，不提供不同租户或项目之间的数据隔离。

| 能力 | 只读用户 viewer | 操作员 operator | 管理员 admin |
| --- | --- | --- | --- |
| 查看项目、任务、证据、历史结果和下载报告/产物 | 允许 | 允许 | 允许 |
| 自己改密、查看和撤销自己的会话 | 允许 | 允许 | 允许 |
| 上传快照、创建项目/扫描、取消和重试、标记漏洞 | 拒绝 | 允许 | 允许 |
| 修改模型凭据、测试供应商/拉取型号、修改队列配置 | 拒绝 | 拒绝 | 允许 |
| 删除项目、任务及快照 | 拒绝 | 拒绝 | 允许 |
| 创建和管理其他账户、查看操作记录 | 拒绝 | 拒绝 | 允许 |

Server 按路由集中校验，未配置权限的路由默认拒绝，覆盖测试要求新路由具有明确策略。Web 依据服务端身份显示真实角色和可用操作，绕过界面也不能取得权限。旧身份响应未包含角色时，Web 显示“角色未上报”，保留历史读取并关闭写操作，不推断管理员权限。原账户迁移为 operator，部署配置指定的管理员由启动过程提升为 admin；数据库事务保护最后一个启用管理员，当前账户和部署管理员有额外修改保护。

Agent 原有私有控制接口继续使用独立 Agent token，不接受用户会话；Web 代理继续拒绝 `/api/internal/`。Scanner 不取得用户会话、角色或业务数据库连接。

## 登录限制与操作证据

登录限制持久化在数据库中：15 分钟内，每个账户 20 次尝试、每个实际连接来源 100 次，成功后清除该账户限制，保留来源总限制。未知账户和旧密码验证均有 Argon2id 时间填充。来源使用 `RemoteAddr`，不信任客户端提供的 X-Forwarded-For；正式 Nginx 代理后的 Server 来源限制是代理整体的限制，账户限制仍独立。拒绝返回 429 与 Retry-After，Web 提示重试时间。这适用于当前自托管共享工作空间；大规模公网入口应按可信代理拓扑另行配置边缘限制。

操作记录保留操作者、固定动作、对象类型/ID、发生/完成时间和结果；不记录请求体、密码、令牌、API Key、查询串或完整错误。创建、修改、删除、任务控制、会话、报告和产物下载及角色拒绝均进入记录。登录失败记录为未认证，避免把未经验证的用户名当成操作者。

受记录的业务操作必须先成功登记，记录存储不可用时返回 503，不放行修改；完成后按接口响应记录成功、失败或拒绝。完成确认写入失败或进程中断可能留下 `started`，Web 明确显示“结果未确认”。它不是与所有业务变更原子提交的总账，也不声称操作一定没有发生。操作记录可按游标读取，并提供原始 JSON 和任务/项目链接。

## 数据与验收

新增 PostgreSQL 011 为增量迁移，仅给 users 增加 role/active/auth_version，以及会话、登录限制和操作记录表。001–010、旧 SQLite schema、执行合同和历史任务格式保持原字节。SQLite 兼容路径补列并创建同等表，使用单连接串行事务；PostgreSQL 用行锁和管理员集合锁处理并发。

验收覆盖密码迁移、签名密钥轮换、旧令牌拒绝、会话归属/到期/容量、密码/角色/停用撤销、并发限速与最后管理员保护、记录分页、存储故障阻止无记录修改、全部公开路由的策略覆盖以及 API 越权。真实浏览器验证创建账户、不同角色界面、历史 HTML 下载、退出失败重试、改密撤销多会话、操作原始证据、限速及旧身份响应；API 客户端测试验证迟到的 401 不清除新会话。正式镜像验收使用禁止外部连接的 SDK 替身网络，验证重启、替换、备份恢复及旧会话撤销。

本地结果：Go Server 和 Agent 回归通过，Scanner 119 项、跨语言合同 137 项、Web 25 项、真实浏览器认证 11 项及正式整栈 11 项均通过。旧 SQLite 与 PostgreSQL 结构升级保留账户、任务和原始证据；依赖边界与运维拒绝保护通过。桌面、移动和深色界面已截图检查，测试资源已清理，现有业务栈未升级。
