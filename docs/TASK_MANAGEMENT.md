# 扫描任务管理

本轮将 PostgreSQL 调度能力接入任务列表、扫描详情和系统设置，沿用既有 UI 与 SDK 默认内部 worker 数。

## 调度与容量

- 三个持久化上限：全局、同一模型配置、同一项目；均为 1–64 的整数。首次访问按服务启动环境初始化，之后以 PostgreSQL 中的配置为准，重启不覆盖。
- 保存配置与任务领取共用 PostgreSQL 事务锁。版本号用于乐观并发控制；旧表单保存返回 409，必须重新加载。
- 降低并发不会杀死运行任务。新任务须等占用降到新上限以下才能领取。
- Agent 每 10 秒上报槽位和心跳，30 秒无上报视为离线。有效总容量是全局上限与在线槽位总数中的较小值，模型/项目上限还会进一步限制领取。
- Agent 槽位仍由 `AXIOM_AGENT_CONCURRENCY` 启动配置决定；每个 Agent 必须设置唯一 `AXIOM_AGENT_ID`。此版本的产物/快照仍位于同一开发机文件系统，不能仅增加异地 Agent 就视为已支持多机执行。
- 队列按本次 `queued_at,id` 排序。受模型或项目配额限制的任务可被暂时跳过，排队位置不是预计等待时间。
- 用户重试重新入队，保留原创建时间。自动租约恢复更新本次排队起点，最多恢复 2 次。
- 取消中任务的执行机失联，租约到期后由调度领取过程将其结束为 canceled，不再创建新扫描。
- 深度扫描内部 worker 数不通过 Axiom 覆盖，沿用已固定 SDK 的默认值 4。任务并发与内部 worker 数是不同维度。

## 执行历史与错误

- 每次执行保留状态、Agent、起止时间、可用的排队时间、错误、进度、归档结果和独立日志目录。
- `result_json` 与当前漏洞、任务终态在同一事务写入。重试清除当前漏洞工作区，但保留旧执行归档。
- 迁移 004 将仍然存在的最新旧版结果归档；已被旧版覆盖的更早结果不能重建，UI 明确标记不可用。缺失旧排队时间显示「—」。
- 归档结果可展开证据/原始 JSON、下载 JSON，并按漏洞指纹与另一次执行对比。「本次未检出」不是已修复结论。
- 历史选择同步切换活动流；主漏洞工作区仍显示当前任务结果，两者有明确文案区分。历史结果不提供当前漏洞状态修改动作。
- 仅对终态错误分类：认证、限流/额度、连接失败、超时、配置不可用、失联、结果格式异常等。保留原始错误；未知原因显示通用执行失败。日志或源代码内的文字不改变任务状态。
- 限流、认证、供应商失败不自动重试，修复后由用户手动重试；自动恢复只针对租约丢失。

## API

| 接口 | 用途 |
| --- | --- |
| GET /api/v1/executions/overview?taskId=ID | 容量、Agent 在线状态、排队原因和本次计时；未指定 ID 返回活动任务 |
| GET /api/v1/settings/execution | 配置、生效版本、是否可编辑、最近 20 次修改记录 |
| PUT /api/v1/settings/execution | 原子保存 global/perModel/perProject/revision |
| GET /api/v1/scans/ID/attempts | 执行历史与结果可用性 |
| GET /api/v1/scans/ID/attempts/N/result | 指定执行的归档漏洞 |
| GET /api/v1/scans/ID/logs?attempt=N | 指定执行的日志 |
| POST /api/internal/executions/presence | Agent 槽位/存活上报，使用现有 Agent token |

配置写入仅允许 `AXIOM_ADMIN_USER` 指定的系统管理员（默认 admin），由服务端验证。其他已登录账户可读。当前没有完整团队 RBAC/租户隔离，不应宣称其已完成。
