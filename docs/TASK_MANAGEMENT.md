# 扫描任务管理

当前调度采用按需执行，沿用 Go Server + Go Agent + Node Scanner、现有 HTTP/产物/JSONL 和 SDK 0.1.25。所有用户扫描操作在 Web 完成。

## 调度与执行状态

- 平台不再设置全局、同一模型配置、同一项目的并发配额。旧配置值和变更记录保留供历史读取，不参与领取；旧 `AXIOM_MAX_ACTIVE_SCANS`、`AXIOM_MAX_MODEL_SCANS`、`AXIOM_MAX_PROJECT_SCANS` 环境变量不再生效。
- Agent 按队列逐次领取并独立启动已授权执行，不再使用固定任务槽位；旧 `AXIOM_AGENT_CONCURRENCY` 不再限制新 Agent。SDK 内部 Worker、组件并发、预算、超时和范围仍取任务中明确选择的配置，不强制写成最大值。
- Agent 每 10 秒上报，30 秒无上报视为离线。新上报明确使用 `dispatchMode: unbounded` 和 `slots: 0`；0 表示无固定槽位，而不是没有执行能力。新 Agent 必须先确认 Server 声明同一调度能力，不能静默退回旧服务端。
- 队列概览使用 `dispatchMode: unbounded`、`effectiveCapacity: null`，展示执行数、排队数及在线节点。旧节点的正数槽位仍可读取，并提示更新；不以虚构的大数表示容量。
- 领取仍使用数据库事务和执行租约，避免重复领取；只选择满足合同能力、执行身份、源码、存储和任务预算条件的任务。费用未知仍需对账；同一 SDK 身份的凭据刷新与撤销继续互斥。这些检查不变更原生 SDK 扫描能力。
- 任务按本次 `queued_at,id` 排序，暂时不满足执行条件的任务可被跳过；排队位置不等于等待时间。组件父任务不再按组件并发权重挤占全局、模型或项目额度。
- 用户重试重新入队并保留历史；自动租约恢复仍遵循已有恢复策略和费用保护。服务中断不等于用户取消；预算任务租约失效后保留未知费用，不能自动重放模型调用。
- Web“扫描执行”替代旧配额表单，仅提供真实状态、刷新和诊断入口。高级诊断把旧配置标为历史；连接到尚未声明新策略的 Server 时明确提示同步升级，不宣称旧配额已经停用。

## 执行历史与错误

- 每次执行保留状态、Agent、起止时间、可用的排队时间、错误、进度、归档结果和独立日志目录。
- `result_json` 与当前漏洞、任务终态在同一事务写入。重试清除当前漏洞工作区，但保留旧执行归档。
- 迁移 004 将仍然存在的最新旧版结果归档；已被旧版覆盖的更早结果不能重建，UI 明确标记不可用。缺失旧排队时间显示「—」。
- 归档结果可展开证据/原始 JSON、下载 JSON，并按漏洞指纹与另一次执行对比。「本次未检出」不是已修复结论。
- 历史选择同步切换活动流；主漏洞工作区仍显示当前任务结果，两者有明确文案区分。历史结果不提供当前漏洞状态修改动作。
- 仅对终态错误分类：认证、限流/额度、连接失败、超时、配置不可用、失联、结果格式异常等。保留原始错误；未知原因显示通用执行失败。日志或源代码内的文字不改变任务状态。
- 限流、认证、供应商失败不自动重试，修复后由用户手动重试；自动恢复只针对租约丢失。

## API

| 接口 | 用途 |
| --- | --- |
| GET /api/v1/executions/overview?taskId=ID | 执行数、Agent 在线状态、排队原因和本次计时；未指定 ID 返回活动任务 |
| GET /api/v1/settings/execution | 当前 dispatchMode、只读旧配置和最近 20 次历史记录；canEdit=false |
| PUT /api/v1/settings/execution | 已退役；管理员请求返回 410，不能恢复配额 |
| GET /api/v1/scans/ID/attempts | 执行历史与结果可用性 |
| GET /api/v1/scans/ID/attempts/N/result | 指定执行的归档漏洞 |
| GET /api/v1/scans/ID/logs?attempt=N | 指定执行的日志 |
| POST /api/internal/v4/executions/presence | Agent 显式调度模式/存活上报，使用现有 Agent token |

旧写入入口保留管理员鉴权后返回明确的退役响应。历史配置、执行记录和报告读取继续保留。

## 数据库与升级

迁移 023 扩展节点槽位约束以保存显式协商的 0 值，不删除旧配置或历史数据。配套 Server/Agent/Web 需要一起更新；没有对应能力声明的 Server 会被新 Agent 拒绝。每个 Agent 仍须使用唯一 ID，已有共享文件系统边界不变。

## 当前回归边界

回归覆盖 PostgreSQL 中 70 个相同模型/项目任务并发领取、旧配额全为 1 时不阻断领取、无重复分配和历史记录保留；Agent 的 128 个同时执行与停止回收；真实 Server/Agent/Scanner 在旧配额及旧 Agent 并发变量为 1 时同时进入 7 个合成 SDK 调用。浏览器覆盖桌面/窄屏状态、删除配额控件、失败保留快照、混合版本提示及历史只读；服务中断继续保留未知费用并阻止重放。

验收使用一次性 PostgreSQL 和明确的 Fixtures / Mock，不调用真实规划、审计、SDK 登录或外部发布，不连接现有业务数据库。下面的 2026-09 交付记录是历史事实，不表示当前并发策略或本轮真实模型验收。
