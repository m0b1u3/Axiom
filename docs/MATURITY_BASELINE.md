# 单机自托管成熟化基线

2026-10-15。保留 Go Server + Go Agent + Node Scanner / SDK，以及 HTTP、共享产物目录和 JSONL。用户扫描操作均在 Web 完成。本轮按用户要求不执行真实审计任务。

## 实现与验收

| 边界 | 已实现行为 |
| --- | --- |
| 完成响应丢失 | 同一结果幂等重试，数据库和尝试保留一份，SDK 仅执行一次 |
| 断网/租约 | 安全续租窗口内终止阻塞心跳，停止 Scanner；历史保留，恢复受次数限制 |
| 进程中断 | Unix Agent 正常退出或强杀会停止 Scanner/SDK 子进程，Scanner 强杀无提交结果时明确失败 |
| 取消失联任务 | 租约过期后 canceled，不重新调用 SDK |
| 大输出 | 持续排空 stdout，9 MiB 单行输出不会卡住任务完成 |
| 自动恢复 | 正式默认 0 次，由用户在 Web 决定重试；开发默认 2 次，可显式配置 |
| 正式部署 | 静态 Nginx Web、同源代理、非 root、只读根文件系统、健康检查、启动校验、日志轮转 |
| 数据维护 | 一致性数据库/产物/密钥备份、哈希校验、仅新环境恢复、应用镜像 ID 核对 |

| 账户与权限 | Argon2id 及旧密码迁移、持久化会话撤销、角色权限、登录限速、Web 会话/账户/操作记录、恢复撤销旧会话；见 [认证基线](AUTHENTICATION_BASELINE.md) |

步骤 6 新增 PostgreSQL 010 仅保存节点运行元数据，001–009 和现有合同定义不改。测试项目已清理，现有业务运行栈未升级。

步骤 7 新增 PostgreSQL 011 仅扩展账户与会话治理；001–010、原 SQLite schema、Agent/Scanner 和执行合同保持原字节。已构建并验收正式镜像，现有业务运行栈未升级。旧 Web 令牌在升级后需重新登录，旧密码成功登录后迁移；[认证基线](AUTHENTICATION_BASELINE.md) 说明签名密钥轮换及共享工作空间的权限边界。

步骤 8 新增 PostgreSQL 012 与可选预算账本，不回填历史任务；001–011、原 SQLite schema、85 个已有合同定义及执行传输不变。生成独立预算快照合同；Scanner 异常费用不再伪装成最终结算。Go Server / Agent 全回归、119 项 Scanner 回归和依赖边界检查通过。新建正式镜像验收项目及其恢复项目已清理，现有业务栈未升级。

步骤 9 新增 PostgreSQL 013 与独立 SQLite 追加表；001–012、原 SQLite schema 和已有执行合同保留。Server 持有容量策略与清理意图，Agent 不含数据库依赖；故障不提前删除元数据，恢复不会自动继续清理。Linux amd64 正式镜像与 macOS 完成验收，Windows Server 编译通过，Windows 清理未认证。现有业务栈未升级。

步骤 10 增加 Apache-2.0、贡献与漏洞报告渠道、CHANGELOG、Issue/PR 模板、`VERSION` 和源码发布检查。Beta 范围固定为 Linux amd64 单机可信用户自托管；源码导出排除运行数据与私有配置，正式 CI 从导出目录构建。安装、冻结 012 → 013 迁移、内部镜像升级和原镜像备份回滚分别记录，首版没有前一公开二进制认证。发布说明及实际远端状态入口见 [发布流程](RELEASE_PROCESS.md) 和 [GitHub Actions](https://github.com/m0b1u3/Axiom/actions)；真实 SDK 验收仍未在本轮执行。业务栈不随发布准备升级。

故障测试使用独立 PostgreSQL、实际 Agent 与 Scanner，仅替换 SDK 模型调用。生产栈测试使用全新项目，Agent 测试网络禁止外部连接，合成发现标记 Fixture。

## 尚需验收或完善

- 真实 SDK 原生进程、工具权限、供应商行为、费用、大仓库性能及长期运行稳定性。
- 供应商账单自动对账与真实费用验收、可恢复暂停。任务累计预算及未知费用的 Web 人工核对已在步骤 8 实现；当前租约恢复仍是重新执行。
- 多租户及项目隔离、SSO/MFA、密码找回、密钥轮换完整流程、不可篡改审计日志，以及大规模与分布式存储治理。账户治理已在步骤 7 实现；单机容量限制、持久化清理及默认历史保留已在步骤 9 实现。
- Windows 强杀进程树、Linux ARM64 SDK 基线、带链接的真实 SDK 状态备份。
- 步骤 1–9 的运行基线与步骤 10 的发布门槛分开记录；后续 SDK 或 Schema 升级须按 [兼容矩阵](../contracts/COMPATIBILITY.md) 先更新消费者，再复验版本组合和历史读取。历史二进制未逐一认证，当前测试使用冻结接口、描述和迁移样例；内部镜像升级不能代替前一公开 Release 的认证。

配置、安装、备份、恢复、回滚见 [部署指南](../deploy/README.md)。
