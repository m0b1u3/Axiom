# 数据库与多任务并发改造建议

## 已核实的现状

- 开发 VPS：4 vCPU、约7.5GiB内存，当前任务数很小。没有证据证明当前请求慢主要由数据库吞吐造成。
- Axiom业务数据与队列使用同一个 SQLite 文件，journal_mode=delete；连接只配置 busy_timeout(5000) 与外键。
- Agent Worker.Run 同步等待 execute 返回再领取下一条，没有执行槽位池。
- Claim 使用事务内 SELECT 后 UPDATE；按最早id取任务，未设计项目公平性与模型并发配额。
- Agent直接打开数据库文件。多机Agent不能仅复制这个文件后继续使用。
- Heartbeat校验agent_id但不校验attempt；Finish和ReplaceFindings按task id更新，没有本次领取的所有权校验；结果写入和终态更新分两次提交。
- 不同扫描共享 ~/.codex/axiom-model-catalog.json，多模型并发会互相覆盖。
- output目录按task id组织；重试复用目录并覆盖日志，不利于保留每轮历史。
- Retry未重置started_at，造成重试耗时跨轮累加。

## 推荐目标

使用 PostgreSQL 保存业务数据和任务队列。初期不必引入Redis或额外消息队列；先把领取、租约、取消与完成做正确。扫描运行在独立进程中，Agent使用有界执行槽位，Server统一提供Agent任务协议；队列、状态与权限检查由服务端管理。

1. **业务数据**：项目、用户、模型配置、快照元信息、漏洞与人工研判记录。建立版本化migration，增加适当外键、检查约束和查询索引。
2. **任务与执行轮次分离**：scan_tasks保存请求；scan_attempts保存每次尝试的owner、attempt、租约、开始结束时间、错误分类、配置快照和产物地址。重试新建attempt，保留旧轮日志。
3. **原子领取**：在短事务中使用FOR UPDATE SKIP LOCKED选择可执行任务，同时写入owner、attempt、lease_until与状态。事务完成后才启动耗时扫描。
4. **租约与提交校验**：心跳、进度、结果提交必须携带task id、attempt和执行身份。所有权或租约失效时拒绝回写，旧执行器取消自身任务。结果与终态应在同一事务内提交，并支持重复提交幂等。
5. **有界并发**：分别控制每个Agent任务槽位、全局任务上限、项目上限、供应商/API Key上限以及单任务内部worker数量。当前机器先以2个任务、每任务有限内部分工做容量测试，不直接承诺固定吞吐。
6. **独立运行目录**：按task/attempt存放工作目录、模型catalog和日志；按SDK能力隔离可变运行状态。不得用共享的可写模型目录实现多模型并发。
7. **数据存储分工**：数据库存可检索的业务记录与执行事件元信息；源码压缩包、报告、大日志和原始产物放文件或对象存储，保存校验和、归属、大小和生命周期信息。避免高频轮询整文件。
8. **任务策略**：取消可追踪，重试有退避和次数上限，区分限流/网络临时故障与配置错误。按项目调度，避免单个大项目占满执行槽位。

SQLite WAL可作为同机低并发过渡方案，但仍只有一个写入者，且不能通过网络共享WAL数据库实现多机Agent。既然目标是企业部署，建议优先建设PostgreSQL路径，而不是长期维护两套完整业务数据库实现。

## 实施顺序

1. 建立PostgreSQL迁移脚本、数据访问层与集成测试，转换现有SQLite数据；校验记录数、关联关系、密钥密文可解密、产物引用。
2. 建立task/attempt与Agent领取、续租、取消、提交协议，修复重试计时与过期执行回写。
3. 隔离每轮运行目录和模型catalog，再增加Agent并发槽位。
4. 开发VPS进行低并发验收，逐步提高并发并测试供应商限流与故障恢复。
5. 停止旧调度器写入后做最终迁移，切换服务，保留数据库备份和可执行回退方案；不做未经验证的双写。

## 验收标准

- 多个执行器同时领取时，同一attempt不被同时成功领取；过期后重领，旧执行器不能覆盖新结果。
- 重复提交不产生重复漏洞或错误终态；结果与任务状态一致。
- 任务重试保留各轮日志，耗时只计算本轮。
- 多模型同时执行不互相覆盖配置或运行目录。
- Agent中断、服务重启、数据库短暂不可用、模型429、取消和超时可恢复且状态可解释。
- 并发达到上限时新任务可持久化排队，API保持可用；观察排队时间、内存、数据库锁等待、模型错误率与成本。

## 当前变更边界

本次按要求删除的是Axiom被动路径守卫及其字段/页面提示/专属测试；不清除历史扫描产物，也不修改SDK本身的执行机制。数据库尚未迁移，多任务并发尚未开启。本文是基于代码和开发VPS实际配置的实施方案。
