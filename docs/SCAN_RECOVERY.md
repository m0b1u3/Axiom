# 扫描中断恢复：SDK 0.1.25 边界与实现

本批保留 Go Server + Go Agent + Node Scanner、HTTP、共享产物目录与 JSONL。用户通过 Web 核验恢复条件、登记中断、恢复结果及确认重新执行。没有新增面向用户的 CLI，没有升级 SDK，也没有调用真实模型、SDK 登录或外部发布。

## 锁定 SDK 的实际能力

结论来自已安装的 `@openai/codex-security@0.1.25` 及 bundled plugin `0.1.94`，不是当前在线版本的能力描述。六个相关源文件的 SHA-256、逐项结论记录在 [恢复能力基线](../deploy/sdk/recovery-baseline.json)；[只读核验程序](../deploy/sdk/recovery-check.mjs) 与 Scanner 回归检查声明、运行时原型和实现指纹。SDK 锁文件、七处受管补丁及其 manifest 保持不变。

| 入口或状态 | 0.1.25 的实际行为 | 本产品语义 |
| --- | --- | --- |
| `CodexSecurity.run()` / `ScanOptions` | 没有 `resume()`、恢复参数或 `__resumeDeepScan`；实现登记新扫描并调用 `codex.startThread()` | Standard / Deep 均不提供跨进程 SDK 断点续扫 |
| `workflowId` | 复用已保存且已完成的扫描；未完成分支再次执行 `#run()` | 不是中断扫描的会话检查点 |
| `parentScanId` | 新登记一个子扫描，使用新的 Scan ID | 新扫描关联，不是原执行续跑 |
| SDK 连接重试、费用耗尽后的结果收集 | 当前进程内部行为 | 不能用来恢复已退出的 Scanner |
| 插件 Deep coordinator 过期处理 | 插件内部状态处理 | 不作为可供本产品调用的 SDK 恢复接口 |
| Axiom 原子结果提交标记 | 结果文件已经写入并有大小、哈希与执行身份 | 可恢复结果入库，不需要模型调用 |

因此本批没有伪造“继续扫描”按钮。真正的断点续扫需要后续单独验收具有该入口的 SDK 版本，或另行设计应用层可持久化的扫描单元；不得把重新执行或父扫描关联标为续扫。

## Web 的三种处理

关闭、刷新、离开浏览器页面不会停止后台任务。执行仍在线时应继续观察原任务，无需恢复或重跑。

1. **登记租约过期中断**：只有原租约已失效时才可操作。即使没有 Agent 在线轮询队列，也可由 Web 将该次执行收敛到失败；已请求取消的任务收敛到取消。此操作不调用 Scanner。费用从活跃变为未知，旧身份不能再提交。
2. **恢复结果入库**：只有该次执行保留完整 `normalized/result.commit.json` 和匹配结果时才可操作。Server 校验后将原结果归入原 attempt；不创建新尝试、不调用 SDK。取消与超时保持原终态，仍可恢复其已提交证据。原中断状态、错误、完成信封、恢复前费用快照、操作者、时间和提交哈希保留在恢复记录与原始 JSON 中。
3. **重新执行**：创建新的 attempt 和 SDK 会话，可能重复分析和产生费用。Web 明确展示该语义，要求勾选确认；请求绑定用户观察到的 task ID、attempt 与状态。状态变化返回冲突，不能静默改为另一种恢复方式。

没有提交标记、只有 SessionEvent、普通日志或原生 SDK JSON 时，不推断扫描完成。保留已保存的部分日志，完整性与最终费用仍为未知。独立 `preflight()` / `validate()` 不使用扫描恢复入口；继续保留原操作、来源证据与未知费用确认规则。

## 校验、账本与并发

- 仅接收操作合同，不接收客户端文件路径。Server 从配置的共享输出根目录定位 `task/attempt-N`，使用 `os.Root` 限制读取边界；拒绝符号链接、非普通文件和跨执行身份。
- 快照检查提交标记、结果大小/哈希、合同及冻结模型。真正入库前再次检查所有引用产物的大小与 SHA-256；总验证量限定 512 MiB，超出时明确拒绝本恢复路径，原数据保持可读。此上限不裁剪或删除报告。
- 恢复与清理共用存储锁；事务锁定原任务，再检查租约、当前 attempt、状态与清理意图。正在清理的任务不能被恢复。
- 恢复结果、漏洞索引、原生派生索引、账本和恢复记录在一个事务内提交；事务失败不留下“已恢复”的记录。相同结果重复提交幂等，不重复记费。
- 恢复只能处理当前尝试。任务重新排队或已有新 attempt 后，旧请求不能覆盖当前任务；旧结果与恢复记录仍可读取。
- 结果恢复没有新的模型支出。已知最终费用进入原次账本；缺失费用继续保持未知，不能按零结算。人工估算及其依据保留，较高的恢复最终费用只会提高记账值，不降低既有金额。恢复记录另外冻结原费用来源、金额、操作者、时间和依据，原人工金额不会因当前累计上调而丢失。
- 总预算任务仍先核对未知费用，再按 `min(单次上限, 剩余总预算)` 下发新尝试。历史未启用累计预算的任务沿用既有语义。
- 正式部署默认自动恢复次数为 0；开发默认 2，可显式配置。历史配置名 `AXIOM_MAX_RECOVERIES` 保留，其行为是租约过期后**自动重新执行**，不是 SDK 断点续扫。Web 使用准确名称展示。

## 合同、存储与兼容

新增两个独立 v1 Schema：`ScanRecoverySnapshot`、`ScanRecoveryAction`，生成 Go/TS 类型。动作仅允许 `interrupt_expired`、`restore_result`、`restart`；不接受 `resume`。跨语言校验覆盖确认、哈希、旧执行、未来版本和恢复前完成信封的身份。

| Web API | 用途 |
| --- | --- |
| `GET /api/v1/scans/{id}/recovery` | 只读核验原执行与可用处理方式，禁止缓存 |
| `POST /api/v1/scans/{id}/recovery` | 角色为 operator/admin；执行明确动作并记录操作日志 |

追加 PostgreSQL 迁移 `017_result_recovery.sql` 保存恢复来源与原错误/完成信封。001–016、已有 Schema、Scanner Job/Description、控制接口版本、SDK 锁与补丁不改。数据库备份自然包含新表，历史表和报告继续保留。SQLite 历史任务可读取并显示结果恢复不支持；不从旧数据推断新能力。

旧 `/retry` 保留既有客户端兼容语义；新 Web 使用带确认和执行身份的恢复动作。旧 Server 缺少新接口时，Web 显示升级提示，保留任务/报告读取，不回退成无确认的重新执行。

## 验收边界

验收使用独立临时 PostgreSQL、正式 Go Agent/Node Scanner 与合成 SDK 模块，浏览器阻止外部请求。SDK 原型/源码能力核验及 Scanner 既有官方 Mock 测试均不调用模型。

覆盖提交前强杀与子进程终止、提交后 Agent 强杀/未入库、重新打开持久状态、缺少标记、截断/哈希/模型/身份错误、产物缺失/修改/链接、并发恢复与重放、重排队后旧执行拒绝、取消/超时、未知费用及人工依据保留、恢复后剩余预算下发、角色权限和旧版本读取。浏览器验证恢复失败保留上下文、重新执行明确确认、故障后重试、部分会话证据、浏览器刷新不重复执行，以及桌面/窄屏界面。

记录目录为 `output/playwright/scan-recovery/`。真实模型中断后质量、供应商账单、具有恢复 API 的未来 SDK 版本仍需另行验收；本批不会升级现有业务 Docker 服务或触发远端 CI。

本地验收：244 项跨语言合同/回归、139 项 Scanner、46 项 Web 单元测试、13 组恢复浏览器场景与 8 组预算浏览器场景通过；Go 全回归与最后费用快照补充后的相关 Store/API/浏览器回归通过。桌面与窄屏共两轮视觉检查，后续费用证据补充只做功能复验，未增加视觉迭代。受保护的 62 个旧 Schema/迁移/SDK 基线文件保持原字节。临时 PostgreSQL 已删除。详细阶段、源码/构建/日志哈希见 `output/playwright/scan-recovery/verification.json`。
