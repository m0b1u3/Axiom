# SDK 0.1.25 组件化审计执行

Web「组件计划」中打开冻结版本，选择审计模型、并发数、时限、每组件上限、
单轮上限与任务累计预算，并确认原生匹配的未知费用后启动。草稿编辑不会改变
已创建任务。此入口始终使用已冻结完整源码的 Standard 组件范围，不继承 Git
base/head 差异范围，也不自动调用 `planComponents`。

## 执行与合同

- Server 保存父任务、冻结计划及每轮请求；Agent 使用原有租约和 Scanner 子进程；
  Node Scanner 调用公开 `runComponentScans`，用其公开 `createSecurity` 接口为每个
  组件注入独立源码副本和分配后的费用上限。
- 一轮父执行有一个租约、一个固定预算授权和多条组件执行记录；组件不是新建
  的独立队列任务，不会各自再次领取父任务的全部预算。
- 新增输入 6 / Job 8 / ScannerDescription 9；控制 API 4、结果 1、进度和事件 2
  保持不变。旧 schema 和旧读者保留，旧节点不能领取或降级执行新任务。
- `ComponentScanRequest`、`ComponentScanReceipt`、`ComponentScanSnapshot`、
  `ComponentScanResult`、`ComponentFindingBinding` 由统一 schema 生成 Go/TS 类型。
  进度使用原有快照扩展，组件活动使用原有结构化事件和 JSONL；结果使用原有结果扩展。
- 迁移 `020_component_scans.sql` 增加父任务配置、每轮请求/快照、组件执行记录。
  源码、冻结版本、历史结果和报告的原有读取方式不改变。

## 并发、预留与未知费用

领取时复用父任务累计费用账本，授权为 `min(单轮上限, 累计预算剩余)`。
选中的组件按顺序均分整数微美元余数，再各自取每组件上限；所有组件在派发前
预留，合计不得超过本轮授权。余额不足以给每个组件至少一微美元时，在 SDK 前拒绝。
本轮未使用的分配不会在并发组件之间反复复用；终值结算后才可用于后续执行。
父授权中未分配给组件的部分同样保守保留至本轮结束。

实际最大并发是配置并发数与本轮组件数的较小值，同时计入 Server 全局、模型、
项目的准入额度；Agent 的进程槽位仍用于父执行。排队诊断与准入使用同一组件权重。
组件源码在执行前后核对摘要；通过核验的临时副本在返回后释放，异常副本和原始
结果保留供检查，共享不可变快照始终保留。

费用由 SDK 估算，不能承诺供应商实际账单不会超出估算。每条组件记录区分预留、
已知费用下界与终值；失败或中断后缺少费用终值时保持未知。组件结果与快照中的
费用下界会进入 Server 账本，即使最终心跳丢失也不会归零。已返回未知费用的组件
会停止继续派发；终态存在未知费用时，必须先通过既有 Web 人工核对流程才能重试。

SDK 会在多个组件产生发现后自动跨组件匹配。0.1.25 没有该阶段的费用回调、费用
上限或公开关闭开关，因此开始匹配后费用标记未知，不能把扫描预算称为包含匹配
费用的硬性总额上限。人工估算有来源和记录，不会改写 SDK 原始未知状态。

## 结果、匹配与证据

每个返回结果保存完整 SDK JSON 和原生输出；业务发现绑定父执行/轮次、原始组件
索引、SDK Scan ID、冻结计划版本/SHA-256、源码 SHA-256/可选 Git HEAD，以及原始
结果文件的大小与 SHA-256。Server 验证身份、授权、分配、发现计数、产物引用及
原始冻结源码/覆盖证据；被 SDK 改写的临时源码结果不能成为冻结源码的有效证据。

原始组件发现保持独立，指纹按组件划分命名空间，避免跨组件原始证据被覆盖。
SDK 的归并组、匹配依据、不确定匹配、关联关系和原生 Markdown 汇总另行保留。
Web 明确表示这是模型推断，不改变人工处置或漏洞验证状态；匹配失败保留独立
发现并显示部分完成。只有费用阶段确实未调用时，才能显示已知 $0。

Web 的组件总览汇集每个组件最近一次执行，并可回到原执行读取发现、证据与产物。
父任务在仍有未完成组件时保持部分完成；单轮的完成状态单独保留。漏洞列表、
原生匹配与报告始终按所选执行/本轮组件范围展示，不声称所有历史发现已经去重。
组件报告带计划/范围说明，不与普通全量扫描做范围不一致的增减对比。
切换历史执行时，漏洞列表从该轮归档读取，使用只读的原始发现；它不代表当前
人工处置状态。HTML/PDF 导出沿用原接口，新增可选 `attempt` 查询参数绑定历史
执行；未提供时仍读取当前投影。历史归档不可用或轮次无效时明确失败，不回退到
当前执行的发现或新一轮组件范围。

## 取消、中断与重新执行

- Web 可以取消父任务，向正在执行的 SDK 调用传递取消；已完成组件、原始报告和
  费用证据保留。取消不是暂停，0.1.25 不提供跨进程断点续扫。
- 租约过期后进入终态、费用未知，不能自动重放模型。原执行存在完整提交结果时，
  仍可通过 Web「扫描中断与恢复」校验后恢复入库，不调用模型。
- Web 只允许选择失败、部分完成、取消或未开始的组件创建新一轮；已完成组件
  被服务端拒绝重放。检查原轮次/状态，防止重复点击或旧窗口创建重复执行。
- 新一轮保留同一父任务、源码、模型及冻结计划，按累计剩余额度重新分配预算。
  原执行记录和已完成结果不迁移、不覆盖。新一轮只匹配本次所选组件，不能据此
  声称与早期成功组件已经重新匹配。单独重跑匹配不是本轮提供的公开 SDK 能力。
- 组件失败与匹配失败分别表示；全部组件完成而匹配失败时，可以读取独立发现和
  匹配错误，不会把已完成组件伪装成可失败重试的对象。

## Web API

| 路径（前缀 `/api/v1`） | 行为 |
| --- | --- |
| `POST /component-plans/{id}/scans` | 指定冻结版本及摘要、模型、预算、并发及时限创建父任务 |
| `GET /scans/{id}/component-executions` | 父配置、每轮请求/组件快照；沿用会话认证和只读权限 |
| `POST /scans/{id}/component-executions/retry` | 携带原轮次、终态、选中索引和明确重新执行确认 |

取消、费用核对、累计预算调整、原执行结果、证据图谱和产物下载沿用原接口。
操作入口需要 `operate` 权限，查看者只能查看与下载。

## 验证与部署边界

统一合同测试包含 Go/TS 双向往返和拒绝场景；Scanner 测试运行实际锁定组件调度器，
仅替换推理与匹配边界，覆盖未知费用、组件/匹配失败、源码改写和模拟模式禁止真实调用。
Server 流程测试使用专用临时 PostgreSQL、真实 Agent/Scanner，覆盖旧节点、并发准入、
费用结算、选择性重试、父任务汇总、取消和失联；Playwright 覆盖纯 Web 工作流。

现有本地 Docker 已同步更新 Server、Agent/Scanner 和 Web，版本为
`component-scans-20261018-01`。升级前备份两套数据库与共享产物并完成独立恢复校验；
迁移 020 保留原数据库容器、数据卷和历史记录。实际页面只读检查与组件交互隔离验收
分别记录，合成计划和审计结果仅写入临时测试环境。

本轮未执行真实规划模型、真实审计、真实 SDK 登录或外部发布。本地验收记录保存在
`output/playwright/component-scans-deployment/`，不随源码发布。后续升级仍按
[部署与恢复指南](../deploy/README.md) 先完成一致性备份；已有新版组件数据时，
应在独立环境恢复配套备份并验证回退，
不能依据空新增表上的旧 Server 启动测试直接回退写入。代码集成与合成验收不等于
真实模型审计质量验收。
