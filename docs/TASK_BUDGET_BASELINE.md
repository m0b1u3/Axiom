# 任务累计预算与费用对账基线

步骤 8 保留 Go Server、Go Agent、Node Scanner / Codex Security SDK，以及 HTTP、共享产物目录、JSONL 传输。创建、调整预算、核对未知费用、取消和重试均通过 Web 完成。本轮只使用合成 SDK 替身，未执行真实审计任务。

## 两个独立上限

| 属性 | 语义 |
| --- | --- |
| `maxCostUsd` | 原有单次 SDK 估算上限，保存在任务与冻结策略中 |
| `maxTotalCostUsd` | 新增任务总预算，涵盖该任务所有执行尝试 |
| 执行下发额度 | 总预算任务取 `min(单次上限, 剩余额度)`；未设单次上限时取剩余额度 |

例如单次上限 $4、任务总预算 $5：第一次下发 $4，最终记录 $3.125；重试下发 $1.875。原有单次上限仍为 $4，不被重试额度覆盖。当前执行的额度一经领取就冻结，运行期间不允许调整任务总预算。

新建快照任务均启用累计记账。未填写总预算时，仅累计费用，重试仍使用原单次上限；未知费用会提示，但不新增累计预算拦截。任务在排队或终态时可以通过 Web 设置或调整总预算，金额不能低于已记录费用。总预算启用后，未知费用必须先核对，增加额度不能绕过核对。

## Server 管理账本

- PostgreSQL 新增迁移 `012_task_budget.sql`：`task_budgets` 保存总预算与修订号，`task_cost_attempts` 保存每次执行的冻结额度、费用下界、最终估算和人工依据。原有 001–011 不改；SQLite 使用独立的追加表定义，原 schema 不改。
- 任务创建与预算元数据同一事务提交；领取与预留额度同一事务提交。并发领取、重试和修订使用原任务锁及预算修订号，Agent 不持有数据库依赖。
- 同一执行的费用回调是累计快照，不是费用增量。只接受有效执行身份及递增进度修订；重复、乱序回调和重复完成不重复加钱。
- 有效最终估算与已观测下界取较大值。最终估算变小不会自动退回额度，Web 明确说明差异，完整原始结果保持不变。
- 金额以整数微美元记账，1 USD = 1,000,000 单位。预算和人工金额最多六位小数；SDK 估算向上取整到微美元。跨语言整数上限为 `Number.MAX_SAFE_INTEGER`，越界估算转为未知并阻止有限总预算再次分配。
- 当前预留额度是冻结上限中尚未记账的部分，不能当成已支出费用。可用余额扣除已记账金额与预留额度，不向后续执行重复分配同一额度。

这些金额是 SDK 或人工估算，不是供应商结算账单。SDK 的停止时机、供应商定价和未上报费用可能导致超出估算上限；本实现不承诺实际账单的硬性支出保证。

## 费用未知的处理

缺失费用、`null` 费用、失联或异常执行保留“未知”，不能默认结算为零。SDK 明确上报的最终零费用可以记为零；最后一次进度零费用不能证明中断后的完整费用为零。

Scanner 中断或恢复部分原生结果时，进度费用和原始证据保持可读，不把回调伪装成最终 SDK 费用。Server 也将旧兼容 Scanner 带执行错误的结果费用视为部分下界，避免旧适配器的回退费用开放累计预算重试。

启用总预算的执行租约过期后不自动重启 SDK，费用转为未知，保留原尝试与结果。未设总预算的任务仍按既有恢复次数设置执行。过期身份提交的结果不得改写账本。

Web 的“核对费用”要求操作者提供本次执行估算及至少四个字符的依据。人工金额不能低于已记录的下界，只允许在任务终态处理未知执行。保存后标记 `manual_estimate`，保留原始观测、最终结果、操作者、时间和依据；它仍不是已验证的供应商账单。读取、调整与核对沿用步骤 7 的角色权限，写操作进入操作记录。

## 合同与兼容

新增 `TaskBudgetSnapshot` JSON Schema，生成 Go / TypeScript 类型，并纳入同一跨语言 conformance 测试。Schema 定义了费用来源、状态、微美元金额、未知尝试、剩余额度和重试资格。API 响应在 Server 验证 Schema。

| Web API | 用途 |
| --- | --- |
| `GET /api/v1/scans/{id}/budget` | 读取快照、各次执行及费用依据 |
| `PUT /api/v1/scans/{id}/budget` | 提交 `maxTotalCostUsd` 与当前 `revision` |
| `PUT /api/v1/scans/{id}/budget/attempts/{attempt}` | 提交明确的 `estimatedUsd`、`note` 与当前 `revision` |

金额省略或 `null` 不能作为人工零费用。过期修订返回 409；非法金额返回 400；预算存储异常返回 503。Web 保留历史结果工作区，显示读取失败并提供刷新，不伪造可用余额。前后端共同阻止总预算耗尽或未知费用的重试。

不增加 Scanner/Agent 原有消息字段或改传输：Server 将冻结后的执行额度放入既有 `policy.maxCostUsd`，由原输入链路传给 SDK。已有 `MaxCostUSD` 能力检查同时适用于仅配置任务总预算的任务。

历史任务不回填累计预算或推断旧费用；快照为 `accountingVersion: 0`，沿用历史单次预算和重试语义。历史任务、尝试、归档 JSON、报告与下载能力保留。SQLite 导入保留有账本源库的数据，旧库缺少账本表时保持原语义。数据库备份恢复保留额度、修订、累计值和未知费用。

- 148 项共同合同测试，覆盖未知、零值、人工来源、非法精度、越界、版本和未知字段。
- PostgreSQL 回归覆盖重复/乱序进度、完成响应重放、并发领取和重试、冻结额度、耗尽、未知费用、旧兼容 Scanner、零费用、保守累计及 SQLite 导入。
- 实际 Go Agent / Node Scanner 测试捕获 SDK 下发参数，验证第二次获得剩余额度、完成 ACK 丢失仅记账一次、进程强杀阻止累计预算自动恢复。
- 真实浏览器覆盖两种预算提交、费用原始快照、调整后重试、未知费用人工核对、历史任务、读取失败、键盘操作；桌面、移动和深色界面截图检查。
- 14 项独立正式镜像整栈验收通过，涵盖累计预算、取消未知费用及备份恢复；Agent 使用禁止外网的测试网络，模型调用 0 次，合成结果均标注 Fixture。

真实 SDK / 供应商费用验收、供应商账单自动对账、可恢复暂停和长期规模测试仍需后续实施。现有业务运行栈未自动升级。
