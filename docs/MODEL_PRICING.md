# 模型单价与 Token 费用

适用于 0.1.0-beta.2、迁移 028。基础计价功能已部署；当前参考部署的实际单价仍未填写。2026-10-29 本地已用独立配置进行 DeepSeek 实际 Token 计价核验，未部署该轮修复，尚未核对供应商账单。

## 配置

在「模型与授权 → 添加 / 编辑模型 → 用量计价」启用按配置单价自动估算，填写币种和实际采购价格。系统不抓取官网价格，不推断折扣，不因保存单价而测试模型。

| 字段 | 规则 |
| --- | --- |
| 币种 | 三位大写代码，如 USD、CNY；不自动换汇 |
| 单价单位 | 每百万 Token；非负十进制字符串，最多六位小数 |
| 输入、输出单价 | 留空表示未知；明确填 0 表示免费 |
| 缓存规则 | 全部输入同价、读取单独计价且写入按普通输入、读取和写入分别计价 |
| 价格依据 | 可记录合同价、折扣或适用时段；不填写密钥 |

选择分开计价后，需要相应价格与实际用量。缺少所需项目，即使其他计数为 0，完整金额仍保持未知。SDK 没有报告缓存写入量时保留未知，不采用 SDK 为展示而归一化的零。

## 计算与用量来源

当前项目费用使用平台配置单价与实际 Token 计算。SDK 内置价格表的独立估算调用和 Web 入口已移除，新扫描也不再接收 SDK 费用回调或将其金额写入平台结果。实际 Token 回调与 Responses usage 采集继续工作；旧费用、人工核对和原始 SDK 归档保持原值，历史兼容接口只读已有记录，不重新计算。

设输入总量 I、缓存读取 R、缓存写入 W、输出 O，对应每百万 Token 单价为 Pi、Pr、Pw、Po：

- 全部输入同价：`(I × Pi + O × Po) / 1,000,000`。
- 读取单独计价：`((I − R) × Pi + R × Pr + O × Po) / 1,000,000`；写入按普通输入。
- 读写分别计价：`((I − R − W) × Pi + R × Pr + W × Pw + O × Po) / 1,000,000`。

推理 Token 已包含在输出中，不重复加一次。十进制价格使用有理数计算，合计后向上舍入一次到该币种的百万分之一，避免逐项浮点误差。计数不一致或越界时金额未知。

经过 Responses 适配器的扫描与独立复核优先采用实际响应 usage 元数据；原生 OpenAI 扫描采用 SDK 实际累计 onUsage，重复累计回调更新观察值，不相加。相同响应回执去重，冲突、缺失或失败回执不能确认完整总额。不支持采集或没有用量的路径继续未知。

中断及缺失终态回执只能保留部分已知下界，不能将最后一次回调当作完整结算。记录同时保留来源、完整性、时间和执行身份。

独立复核在关闭传输并收齐已发送请求的回执后，将输入、输出、缓存命中、推理用量、总 Token 与请求数写入结果和最终进度快照的 `extensions.executionUsage`。统计不依赖是否已填写单价，任务费用接口可在金额未知时继续返回已知用量。失败或报告不完整时保留已观测用量并标为不完整；未返回缓存写入量时保存 `null`，只有接口明确返回零才记录零。此补充只应用于新执行，不从历史日志回填用量，不重算历史单价或费用；原生 SDK 费用未知仍保留原值。

2026-10-30 本地补齐跨组件匹配统计，先完成隔离验收，随后完成[小项目真实复测](acceptance/component-matching-real-20261030.json)，尚未部署 VPS。每个组件与匹配阶段使用独立的用量采集连接；关闭连接、收齐请求回执后归档匹配的输入、输出、缓存读取、缓存写入、推理、总 Token 和请求次数。整次执行只合并这些互不重叠的统计，不再叠加同一请求的 SDK 累计回调。

匹配明细使用标准 `TokenCostEstimate`，保存在结果及进度的 `extensions.componentMatchingEstimate`，同时封存在 `raw/codex-security/component-matching-token-usage.json`。整次任务的合并用量继续使用 `extensions.executionUsage`，由服务端按本次已冻结的价格独立计算；匹配金额、版本或单价与冻结依据不符时拒绝入库。分项各自向上取整，总额按合并后的 Token 统一计算，因此分项显示值的相加可能存在百万分之一币种单位的舍入差异。

本地真实任务 30 中，145 份组件响应的逐次 Token 与独立连接统计一致，匹配的 1 次请求另行计入。两个组件估算 `$0.197650` / `$0.200913`，匹配 `$0.000765`；整次执行合并 Token 后为 `$0.399327`，与分项已舍入值相加相差 `$0.000001`。Python Decimal 独立验算、API 入账、原始归档及网页下载一致。两次复核另行估算 `$0.006777` / `$0.006094`。V2 消息探针有一个被原生抢占取消的响应，其完整用量和费用仍未知；这些估算没有经过供应商账单核对，不回填历史任务 26 的未知匹配费用。

匹配回执完整且必要单价、用量齐全时显示估算；缺失、冲突、失败或缺少所需缓存计数时，完整费用保持未知，可确认的部分仅作为下界。写入量未返回仍为 `null`。没有派发匹配请求的范围保留明确零请求事实；已开始匹配却没有回执，不能据此推断免费。旧 `componentScan.snapshot.matching.costState` 保留其兼容语义，新界面优先读取独立的配置单价估算；缺少新字段的历史记录仍显示原来的未知状态，不读取旧日志补算。

## 历史与预算

每次执行被领取时冻结匹配模型配置的单价、版本、模型和供应商。改价只影响以后开始的执行；删除模型配置仍保留历史快照，不给旧执行追溯补价。单价不传入 SDK 模型请求，也不改变 Responses / Schema 协议。

新建扫描设置有限预算时，模型必须配置完整 USD 单价；缺项在任务创建前返回明确错误，未知价格不会按免费处理。领取执行时沿用既有价格快照，Agent 以独立的 `token-budget.json` 参数文件传给 Scanner，执行身份、供应商和模型必须匹配；SDK 0.5.0、Responses 与 Schema 保持不变。新执行的该预算由平台按配置单价控制，不再把它交给 SDK 内置价格表；旧节点未声明预算能力时不得领取。

Responses 适配器在每次发送前检查预算，在收到请求回执后核对必要用量并累计估算；达到上限、用量缺失或矛盾时停止继续发送，保留中间候选、证据和已知费用下界。原生连接通过 SDK 累计用量观察及取消信号控制；观察可能延迟。并发中已经发出的请求仍可能产生费用，因此这始终是估算上限，不是供应商账单硬上限。独立复核和组件操作保留各自费用与预算边界，不能把新建扫描的验收范围扩大到所有 SDK 工作流。

组件扫描由平台把父执行额度分配给所选组件，每个组件的 Responses 连接按自己的冻结单价和实际回执累计，包含 SDK 为该组件创建的子任务。不再向 SDK 传入要求内置模型价格表的 `maxCostUsd`，也不把 SDK 费用回调作为平台费用。组件缺少完整终态用量时停止后续派发，已经通过源码检查的结果继续保留。跨组件匹配仍须单独确认可能新增且不受组件额度限制的费用；取得完整回执后可按冻结单价估算。统计补齐没有新增匹配费用硬上限，也不能把组件费用之和当作包含匹配的完整费用。

USD 估算接入现有 USD 预算账本，其他币种单独展示。非 USD 金额不会换算或混入 USD 预算。SDK 原始费用、平台价格估算、人工核对各有来源；原生 SDK 结果不会被覆盖。独立复核仍没有 SDK 费用上限保证，自动估算不增加硬性账单上限。

在执行详情「任务预算与费用」展开「按用量估算」，查看冻结版本、单价、Token 和未知原因；「原始费用快照」可读取完整依据。所有自动与人工金额均为估算，不能标为供应商已结算账单。

## 本地验收使用的价格

2026-10-29 根据使用者提供的 [DeepSeek 官方价格文档](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)及其[美元价格页](https://api-docs.deepseek.com/quick_start/pricing/)，新建本地验收专用连接，未修改原模型配置或历史费用。冻结的高峰 USD 单价为每百万普通输入 Token `$0.30`、缓存读取 `$0.006`、输出 `$1.20`，采用缓存读取单独计价。缓存写入没有独立返回时保持 `null`，本计价规则不要求写入计数。

这是人工确认来源的验收价格快照，不是新增自动抓价功能。文档另有非高峰价格；跨时段、合同折扣或币种不同的实际账单需另外核对。本轮始终按冻结高峰价格估算，不自动识别或切换非高峰价格，也不给未配置价格的旧任务补算费用。

## 升级与回退

Server、Agent / Scanner、Web 同步升级，Server 先执行 `028_model_token_pricing.sql`。迁移给模型增加空单价与版本 0，新增空执行快照表，并扩展费用来源枚举；不改已有费用、模型凭据或历史结果。SQLite 导入与重新打开保留新元数据。

已产生新计价记录后，旧版本可能不认识 configured_pricing 或新费用快照；回退前须在独立副本演练读取、写入及合同兼容。保留当前数据和密钥，完整备份恢复使用独立项目，不能以旧备份覆盖新产生的历史。
