# 模型单价与 Token 费用

适用于 0.1.0-beta.2、迁移 028。功能已部署并通过隔离验收；当前参考部署的实际单价未填写，新计价尚未进行真实模型或供应商账单验收。

## 配置

在「模型与授权 → 添加 / 编辑模型 → 用量计价」启用按配置单价自动估算，填写币种和实际采购价格。系统不抓取官网价格，不推断折扣，不因保存单价而测试模型。

| 字段 | 规则 |
| --- | --- |
| 币种 | 三位大写代码，如 USD、CNY；不自动换汇 |
| 单价单位 | 每百万 Token；非负十进制字符串，最多六位小数 |
| 输入、输出单价 | 留空表示未知；明确填 0 表示免费 |
| 缓存规则 | 全部输入同价、读取单独计价且写入按普通输入、读取和写入分别计价 |
| 价格依据 | 可记录合同价、折扣或适用时段；不填写密钥 |

选择分开计价后，需要相应价格与实际用量。缺少所需项目，即使其他计数为 0，完整金额仍保持未知。SDK 没有报告缓存写入量时保留未知，不采用 SDK 为展示而归一化的零。

## 计算与用量来源

设输入总量 I、缓存读取 R、缓存写入 W、输出 O，对应每百万 Token 单价为 Pi、Pr、Pw、Po：

- 全部输入同价：`(I × Pi + O × Po) / 1,000,000`。
- 读取单独计价：`((I − R) × Pi + R × Pr + O × Po) / 1,000,000`；写入按普通输入。
- 读写分别计价：`((I − R − W) × Pi + R × Pr + W × Pw + O × Po) / 1,000,000`。

推理 Token 已包含在输出中，不重复加一次。十进制价格使用有理数计算，合计后向上舍入一次到该币种的百万分之一，避免逐项浮点误差。计数不一致或越界时金额未知。

原生扫描取 SDK 实际累计 onUsage，重复累计回调更新观察值，不相加。经 Responses 适配器的独立复核从响应 usage 元数据观察请求；相同回执去重，冲突、缺失或失败回执不能确认完整总额。不支持采集或没有用量的路径继续未知。

中断及缺失终态回执只能保留部分已知下界，不能将最后一次回调当作完整结算。记录同时保留来源、完整性、时间和执行身份。

## 历史与预算

每次执行被领取时冻结匹配模型配置的单价、版本、模型和供应商。改价只影响以后开始的执行；删除模型配置仍保留历史快照，不给旧执行追溯补价。单价不传入 SDK 模型请求，也不改变 Responses / Schema 协议。

USD 估算接入现有 USD 预算账本，其他币种单独展示。非 USD 金额不会换算或混入 USD 预算。SDK 原始费用、平台价格估算、人工核对各有来源；原生 SDK 结果不会被覆盖。独立复核仍没有 SDK 费用上限保证，自动估算不增加硬性账单上限。

在执行详情「任务预算与费用」展开「按用量估算」，查看冻结版本、单价、Token 和未知原因；「原始费用快照」可读取完整依据。所有自动与人工金额均为估算，不能标为供应商已结算账单。

## 升级与回退

Server、Agent / Scanner、Web 同步升级，Server 先执行 `028_model_token_pricing.sql`。迁移给模型增加空单价与版本 0，新增空执行快照表，并扩展费用来源枚举；不改已有费用、模型凭据或历史结果。SQLite 导入与重新打开保留新元数据。

已产生新计价记录后，旧版本可能不认识 configured_pricing 或新费用快照；回退前须在独立副本演练读取、写入及合同兼容。保留当前数据和密钥，完整备份恢复使用独立项目，不能以旧备份覆盖新产生的历史。
