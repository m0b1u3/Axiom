## 已发现并修复的缺失

| 原问题 | 修复后的行为 |
| --- | --- |
| 扫描列表、项目快照删除仍使用旧确认入口 | 与详情/资产统一为清理计划预览、保护说明、明确执行和失败继续；无旧接口回退 |
| 新建扫描吞掉项目/快照/模型读取错误 | 分对象显示失败，可重新读取；保留填写内容，读取失败期间不提交扫描 |
| 工作台向只读账户展示新建入口 | 按统一账户能力显示操作；后端鉴权不变 |
| 未知路径显示空白工作区 | 提供领域内的不存在页面与返回入口；对象路径仅接受正整数 |
| 下拉触发器内嵌清除按钮，缺少名称且可能保留旧值 | 清除按钮独立、可键盘访问；受控空值清除旧选择 |
| 漏洞状态保存失败后，下拉框仍显示未保存的新状态 | 共享选择器严格跟随父级确认值，失败保留原状态；状态保存中禁止重入 |
| 表格只有行点击/Enter，列宽固定 | 增加上下键/J/K/Home/End、焦点/选中状态、鼠标与键盘列宽调整；内部操作不冒泡打开行 |
| 列表读取失败时仍出现“没有数据” | 错误时不展示假空态；已有数据明确标为上次成功读取的快照 |
| 漏洞池快速筛选可能被正在读取的请求吞掉 | 服务端按全量聚合结果查询；URL还原、输入防抖和请求世代校验保留最新条件 |
| 漏洞/扫描对比读取失败静默消失或只有瞬时通知 | 保留页面内错误及重读入口；失败不冒充无发现 |
| 漏洞列表读取失败时，统计仍显示为零 | 总数使用Server已保存的数量，未能读取的严重度统计显示未知；重试不沿用上次读取错误 |
| 取消/重试失败只出现短暂通知 | 持久显示操作失败及保留状态，用户可重试原操作 |
| 项目/模型保存失败与预设读取失败缺少稳定入口 | 弹窗内显示错误、保留字段；供应商列表可重读 |
| 设置分区只识别storage参数 | 全部分区支持深链接与刷新；越权分区回到可读取的调度页 |
| 代码查看器异步加载失败可能造成未处理异常 | 明确报错并保留可访问的原始文本 |
| 独立使用加载组件时没有显示加载状态 | 独立/包裹两种使用方式均显示可访问的加载状态 |
| 调度配置重读期间仍允许编辑，晚到响应覆盖输入 | 重读期间锁定字段，409保留输入，由用户明确重读后再保存 |
| 窄屏隐藏侧栏仍能获得键盘焦点 | 隐藏导航与被覆盖工作区分别设为inert；打开后约束焦点，Esc返回触发器 |
| 极长名称撑高整行、接口截断可能被误认为全量 | 两行预览保留完整名称与详情入口；全量分页和服务端检索替代截断列表，旧数组接口保留 |

- 可恢复暂停、自动修复、SSO/MFA、密码找回不属于已实现首版能力；不添加无后端支持的按钮。
- 本轮不升级当前业务环境，不改动历史任务/报告、数据库迁移、合同或SDK补丁。
- `PRODUCT.md` 的平台字段格式和SQLite/串行Agent历史描述已过期；本轮以当前实现和成熟化基线判定，不用旧设计上下文认定功能完成。

## 重现与证据

在 `code-audit-web` 中运行 `npm run build` 和 `npm test`，使用专门的 `axiom_test_input*` PostgreSQL 数据库，在 `code-audit-server` 中运行：

```sh
AXIOM_TEST_DATABASE_URL='postgres://postgres:fixture-password@127.0.0.1:5432/axiom_test_input_frontend?sslmode=disable' \
AXIOM_TEST_WEB_INPUT=1 \
AXIOM_TEST_FRONTEND_REPORT_DIR="$PWD/../output/playwright/frontend" \
go test -count=1 -timeout=8m -run '^TestFrontendPageActionsAndRecovery$' -v ./internal/httpserver
```

数据库名称和本机地址有强校验，测试会清空该独立测试库。不得配置业务数据库。macOS默认使用已安装的Google Chrome；Linux使用Playwright管理的Chromium，也可用 `AXIOM_TEST_BROWSER_PATH` 指定本机浏览器。

`output/playwright/catalog/report.json` 保存全量分页场景、构建/脚本哈希与12张截图；重现入口见 [查询基线](CATALOG_PAGINATION.md)。
