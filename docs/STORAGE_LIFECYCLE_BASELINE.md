# 存储容量与数据生命周期基线

2026-10-15。步骤 9 保留 Go Server + Go Agent + Node Scanner / SDK，以及现有 HTTP、共享产物目录、JSONL 传输。容量策略、清理预览、执行、继续及放弃清理均在 Web 完成。本轮未执行真实审计任务。

## Web 入口与容量

系统设置 → 存储与清理，展示扫描产物和源码快照的逻辑文件量、所在卷总容量、当前用户可用空间、采样时间及探测结果。两个目录可能共享同一卷，容量不能相加；逻辑文件量也不等于实际占用块数或保证可回收的空间。小文件使用 B / KiB 显示，不将正数四舍五入成零。

失败的容量探测显示未知，目录占用检查未完成也保留未知。Web 保留上次成功快照时明确标记过期状态，不能把读取失败当成空间充足。原始存储快照及清理记录可直接展开检查。

| 策略 | 默认与边界 |
| --- | --- |
| 领取前保留空间 | 1024 MiB；管理员可在 Web 调整，0 只关闭数值阈值 |
| 遗留目录宽限期 | 顶层目录修改时间超过 24 小时；可设 1–8760 小时 |
| 未知容量 | 阻止新领取，不按零空间或无限空间解释 |
| 自动删除历史数据 | 始终关闭；无后台定时清理，也不自动继续中断清理 |

Server 在四个既有领取接口上使用同一检查，读取当前策略并在领取事务分配执行前检查卷空间。空间不足或探测未知时保持排队，Web 显示对应原因。已有执行的心跳、取消、完成提交及过期租约处理继续进行，不因容量门槛停止接收结果。

这是领取时的容量检查，不是扫描输出的硬性配额。已经运行的扫描或其他进程仍可能消耗空间；扫描期间磁盘写满仍需按执行错误和未知费用规则处理。

## 保护规则与清理预览

默认预览只选择超过宽限期、没有引用的受管理目录。以下对象保留：

- 任何任务及执行尝试引用的目录，包括运行中任务和历史报告。
- 费用尚未完成核对的执行证据，是否设置任务总预算不影响保护。
- 已登记源码快照、任务使用的源码目录及其覆盖范围；父级目录引用同样保护子目录。
- 尚在宽限期的目录、已有未完成清理记录的对象。
- 符号链接、特殊文件、跨设备内容或无法完整检查的对象。
- 缺少数据库归属、但包含结果、提交标记、进度或事件文件的目录，保守标为疑似未登记执行证据。

管理范围仅限配置的扫描产物和源码快照根目录，拒绝删除根目录本身或访问范围外的路径。不扫描系统临时目录。新的上传临时归档保存在快照根内的私有 `.uploads` 目录，中断遗留可进入同一预览流程；已登记快照不会因此变成默认清理对象。

任务或快照的显式删除仍需管理员操作。Web 先展示删除计划，再明确执行；运行中任务、未知费用和其他对象引用会阻止删除。共享顶层目录或不属于当前管理根的历史路径会保守拒绝清理，保留数据，不猜测归属。旧删除 API 仍可调用，但同样经过持久化清理流程及保护检查。新 Web 不会在旧 Server 缺少治理接口时自动回退到直接删除。

预览不删除文件，15 分钟后须重新预览。计划最多包含 200 项，保护对象只展示有限样本，并明确标记截断；大量历史对象不会挤掉全部可清理候选。文件内容指纹、引用和宽限期在执行前复核，变化后拒绝执行。

## 可恢复清理

新增 PostgreSQL 迁移 `013_storage.sql` 和独立 SQLite 追加表：

- `storage_settings` 保存阈值、宽限期与修订号，采用修订号校验更新。
- `storage_cleanup_jobs` 保存清理意图、受管理根绑定、对象、内容指纹及每项处理阶段。
- 原 001–012 迁移、旧 SQLite schema 和历史任务记录不回写。

流程为：

1. 创建并保存预览，明确选择后提交清理。
2. 重新核对引用、费用、根目录和文件内容，记录执行开始。
3. 在同一管理根内将对象隔离到 `.axiom-trash/<记录编号>-<条目序号>`，持久化每项阶段。
4. 移除隔离对象；只有全部文件处理完成后，才在同一数据库事务删除明确选中的任务或快照元数据，并完成记录。

删除失败、请求中断或超时保留记录和未完成阶段，不提前丢弃任务元数据。Web 可查看每项状态并继续处理。文件已隔离但阶段尚未确认就发生重启时，继续操作会识别原隔离目录；不会删除原路径后来重建的数据。完成操作可幂等重试。

尚未隔离的失败计划可以在 Web 放弃后重新预览。已有隔离数据时拒绝放弃，须先处理该记录；放弃不会恢复已经移除的文件。恢复应用或数据库本身不会自动执行清理。

文件操作使用受管理根描述符，隔离重命名在已认证 Unix 平台使用描述符操作，清理不跟随符号链接并拒绝跨设备遍历。跨进程数据库锁协调清理与领取、重试、上传，清理期间重试不能覆盖正在处理的目录。等待锁的连接使用独立连接池，避免耗尽清理记录提交所需的数据库连接；心跳与结果提交不等待该文件维护锁。

## 合同、权限与备份

新增 `StorageSnapshot`、`CleanupJob` Schema，生成 Go / TypeScript 类型并纳入共同合同测试。既有执行消息、兼容矩阵与传输方式不改，Agent 不新增数据库依赖。

| API | 权限与用途 |
| --- | --- |
| `GET /api/v1/storage` | 读取容量与策略 |
| `PUT /api/v1/storage/policy` | 管理员更新策略，携带修订号 |
| `GET /api/v1/storage/cleanup` | 管理员读取清理记录 |
| `POST /api/v1/storage/cleanup` | 管理员生成预览，仅提交对象身份 |
| `GET /api/v1/storage/cleanup/{job}` | 管理员读取完整记录 |
| `POST /api/v1/storage/cleanup/{job}/execute` | 管理员执行或继续，携带修订号 |
| `POST /api/v1/storage/cleanup/{job}/cancel` | 管理员放弃尚未隔离的计划 |

清理请求不能直接指定文件路径。写操作沿用步骤 7 的权限、操作记录及失败时拒绝无记录写入的规则。旧任务、历史报告与结果下载入口继续保留。

一致性备份先关闭 Web 写入并停止 Server，再检查扫描队列与停止 Agent；中断清理的记录和隔离目录一起备份。恢复到新项目后，原策略与清理意图保留，未完成记录不会自动运行，由管理员在 Web 继续。受管理根配置改变时不自动重定位待清理文件，保留数据并拒绝继续。SQLite 导入同样保留可选策略与清理记录，旧库缺表时保持原语义。

## 验收与限制

- 164 项 Go / TS 合同测试，覆盖零值、未知、字节范围、边界路径和清理状态；既有合同定义与兼容矩阵保留。
- SQLite / PostgreSQL 故障回归覆盖历史和未知费用保护、父级引用、新增引用、内容变化、隔离后确认丢失、同名数据重建、删除失败、放弃重建计划及策略/记录导入。
- 并发锁回归验证领取等待不会阻塞清理记录提交，容量不足时仍能收尾过期租约。
- 真实浏览器覆盖容量与保留规则、原始快照键盘操作、策略阻塞/恢复、保护预览、失败继续、存储读取失败及关闭删除预览；桌面、移动与深色界面已检查。
- 正式隔离镜像整栈验收包含真实 Agent 的容量阻塞、历史证据 SHA 保留、清理意图备份恢复，以及恢复后从 Web 明确继续；SDK 仅为替身，模型调用 0 次。

Linux amd64 正式镜像与 macOS 本机完成清理测试。Windows Server 编译通过，Windows 清理尚未认证，界面保留数据并禁用清理；容量探测实现仍需 Windows 运行验收。多机独立磁盘、网络文件系统特性及大规模长期性能未在本轮认证。当前清理协调面向既有共享卷部署，不能推断为分布式存储管理。

现有业务运行栈未自动升级。测试项目与卷在验收后清理，历史数据默认保留。
